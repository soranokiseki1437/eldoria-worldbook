# 世界书工程运维排错与踩坑指南 (Troubleshooting)

> 本文档汇总自 `.learnings/LEARNINGS.md` 与历史提交中经过实战验证的踩坑经验，指导运维异常时的精准处理。

---

## 一、 常见异常与排错处理

### 1. “自由探索——X” 系列重复标题审计（LRN-20260804-001）
- **现象**：在审计 `_sex_index.txt` 或一致性检查时，会发现多处同名章节（如“自由探索——营地的深夜”出现在 Ch609/575/238 等不同阶段编号中）。
- **判定**：**这是项目的预期设计，绝非数据异常！**
- **对策**：不要求强制去重；重编号或标题匹配时，对同名章节需结合上下文阶段人工核验，不可当做 bug 误删。

### 2. 重编号后索引与弧线整体脱节（LRN-20260804-002）
- **现象**：全局重编号后，`_sex_index.txt` 和 `_连续叙事弧线章节总览.md` 的章节号仍为旧编号。
- **对策**：
  1. 运行 `python scripts/fix_index_numbering.py` 生成按标题匹配的编号候选文件。
  2. 手工处理特殊条目：① 非整数编号（如 615.5）；② 拆分章节缺（上/中/下）后缀的条目；③ 标题含特殊标点或引号的条目。
  3. 弧总览部分必须按“以文件系统实际存在为准”逐条验证，**严禁使用全文件简单字符串替换**（会造成二次双重转换）。
  4. 阶段表章数按阶段文件夹实际文件数重算。

### 3. 文档避免写死章节数与章节 ID（LRN-20260804-003）
- **铁律**：除自动化映射表外，任何规则文档、CLAUDE.md、Skill 指令中**严禁硬编码死具体章节数目（如“844章”）或章节 ID（如“Ch160”）**，因为每次重编号或新增章节都会导致其失效。
- **引用标准**：需要引用具体章节时，一律统一使用《章节全名》（如《暮色里的通讯——暖岩石上的意外》）。

### 4. 校验器盲区排查清单（FEAT-20260804-001）
`check_consistency.py` 脚本虽然全绿，但仍需防范三类盲区：
- **分类内重复行**：检查 `_sex_index.txt` 同一标签内是否存在完全重复的 (编号, 标题) 行。
- **未分类残留**：条目若已归入其他具体性行为标签，必须从“未分类”段中彻底删除。
- **弧总览乱序**：弧总览各行必须按起始章节号严格升序排列。
