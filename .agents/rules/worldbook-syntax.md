# 世界书工程语法与结构铁律

> **适用范围**：所有涉及世界书构建、章节创建、条目修改、脚本执行与 JSON 输出的操作。

---

## 一、 数据权威性原则（Single Source of Truth）

1. **TXT 文件是唯一权威源**：
   - 所有的章节内容以 `docs/story/{阶段}/{ID}：{名称}.TXT` 为绝对权威。
   - 所有世界观、角色、地点、生物以 `docs/{chapter,character,creature,location,magic,npc,world,affection}/` 为准。
2. **构建物不可手改**：
   - `output/Eldoria_V*.json` 是通过脚本全量生成的派生品，**绝不可手动编辑**。
   - 修改流程铁律：**修改 TXT → 运行脚本构建 → 验证**。

---

## 二、 酒馆（SillyTavern）JSON 结构规范

1. **Object 格式铁律（致命红线）**：
   - `entries` 必须是 Object 形式，键名为字符串数字：`{"0": {...}, "1": {...}}`。
   - **绝对禁止输出为 Array 数组 `[{...}]`**，否则酒馆导入会直接拒绝或解析崩溃。
2. **13 字段精简标准**：
   每个条目仅包含标准 13 字段，严禁产生 `extensions` / `originalData` / `characterFilter` 等冗余膨胀字段：
   ```text
   uid / key / keysecondary / comment / content / constant /
   selective / order / position(0/1/4) / depth / group /
   excludeRecursion / preventRecursion
   ```
3. **递归控制字段规则**：
   | 字段 | 含义 | 章节条目 | 概念条目(角色/地点/生物) | constant系统条目 |
   |:---|:---:|:---:|:---:|:---:|
   | `excludeRecursion` | 不可递归：不被其他条目激活 | `true` | `true` | `false` |
   | `preventRecursion` | 防止进一步递归：激活后不触发下级 | `false` | `true` | `false` |
   *(设计逻辑：章节仅由 key 直接触发，但可递归触发角色与地点；概念条目作为叶子终端节点，不触发下级递归。)*

---

## 三、 章节体系与命名规范

1. **章节编号与命名**：
   - 纯数字 ID，单线推进，无分支。
   - 文件名格式严格为：`{ID}：{前半段}——{后半段}.TXT`（注意中文全角冒号与双破折号）。
   - 章节触发 Key：`['第N章']`，`selectiveLogic: 0`。
2. **章节 TXT 必填字段体系**：
   - `ID`：纯数字
   - `名称`：前半段——后半段
   - `NSFW`：是 / 否
   - `性行为等级`：0-10（NSFW为“是”时必填）
   - `阶段`：序章 / 试探和暧昧 / 挑逗和接受 / 渐进接触 / 跨线 / 享受和掌控 / 放纵 / 终局 / 后日谈
   - `第三者`：姓名（身份）（有第三者时必填）
   - `黎恩知情`：知情状态与态度
   - `好感影响`：`{角色名}: ±{value}`
   - `情境`：列表形式，至少 3 条，包含起因、动作、感官与推进
   - `核心`：章节设计意图
   - `章节任务`：1 句话核心任务
   - `章节终止条件`：清晰的事件落地条件列表
3. **索引文档约定**：
   - `docs/story/_sex_index.txt` 是手工维护的类型权威源，脚本只读不写。
   - 规则与索引文档中**禁止硬编码死章节数目与章节 ID**（重编号后会过时），引用章节时一律使用章节全名《书名号引用》。
