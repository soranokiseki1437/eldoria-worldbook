# 世界书工程语法与结构铁律

> **适用范围**：所有涉及世界书构建、章节创建、条目修改、脚本执行与 JSON 输出的操作。

---

## 一、 数据权威性原则（Single Source of Truth）

1. **TXT 文件是唯一权威源**：
   - 所有的章节内容以 `docs/story/{阶段}/{ID}：{名称}.TXT` 为绝对权威。
   - 所有世界观、角色、地点、生物以 `docs/{chapter,character,creature,location,magic,npc,world,affection}/` 为准。
2. **构建物不可手改**：
   - `output/Eldoria_V*.json` 是通过脚本全量生成的派生品，**绝不可手动编辑**。
   - 修改流程铁律：**修改 TXT → 运行脚本构建 → 验证**。

---

## 二、 酒馆（SillyTavern）JSON 结构规范

1. **Object 格式铁律（致命红线）**：
   - `entries` 必须是 Object 形式，键名为字符串数字：`{"0": {...}, "1": {...}}`。
   - **绝对禁止输出为 Array 数组 `[{...}]`**，否则酒馆导入会直接拒绝或解析崩溃。
2. **13 字段精简标准**：
   每个条目仅包含标准 13 字段，严禁产生 `extensions` / `originalData` / `characterFilter` 等冗余膨胀字段：
   ```text
   uid / key / keysecondary / comment / content / constant /
   selective / order / position(0/1/4) / depth / group /
   excludeRecursion / preventRecursion
   ```
3. **递归控制字段规则**：
   | 字段 | 含义 | 章节条目 | 概念条目(角色/地点/生物) | constant系统条目 |
   |:---|:---:|:---:|:---:|:---:|
   | `excludeRecursion` | 不可递归：不被其他条目激活 | `true` | `true` | `false` |
   | `preventRecursion` | 防止进一步递归：激活后不触发下级 | `false` | `true` | `false` |
   *(设计逻辑：章节仅由 key 直接触发，但可递归触发角色与地点；概念条目作为叶子终端节点，不触发下级递归。)*

## 三、 章节体系与命名规范

1. **章节编号与命名**：
   - 纯数字 ID，单线推进，无分支。
   - 文件名格式严格为：`{ID}：{前半段}——{后半段}.TXT`（注意中文全角冒号与双破折号）。
   - 章节触发 Key：`['第N章']`，`selectiveLogic: 0`。
2. **章节 TXT 必填字段体系**：
   - `ID`：纯数字
   - `名称`：前半段——后半段
   - `NSFW`：是 / 否
   - `性行为等级`：0-10（NSFW为“是”时必填）
   - `阶段`：序章 / 试探和暧昧 / 挑逗和接受 / 渐进接触 / 跨线 / 享受和掌控 / 放纵 / 终局 / 后日谈
   - `第三者`：姓名（身份）（有第三者时必填）
   - `黎恩知情`：知情状态与态度
   - `好感影响`：`{角色名}: ±{value}`
   - `情境`：列表形式，至少 3 条，包含起因、动作、感官与推进
   - `核心`：章节设计意图
   - `章节任务`：1 句话核心任务
   - `章节终止条件`：清晰的事件落地条件列表
3. **索引文档约定**：
   - `docs/story/_sex_index.txt` 是性行为分类权威源。
   - 规则与索引文档中**禁止硬编码死章节数目与章节 ID**（重编号后会过时），引用章节时一律使用章节全名《书名号引用》。

## 四、 章节增删与方案维护联动铁律（Mandatory Sync Rule）

1. **增减章节必须双向同步索引与弧总览**：
   - 但凡增加或减少章节，必须立即同步更新：
     - `docs/story/_sex_index.txt`：平移受影响编号，且**必须收录/移除对应章节的性行为标签，更新分类计数**；
     - `docs/story/_连续叙事弧线章节总览.md`：平移所有受影响的弧线引用、更新各阶段章数、首尾章锁定及总章数统计；
   - 强制运行 `python scripts/check_consistency.py`，确保 100% 绿灯。
2. **方案完成即删原则（零历史痕迹）**：
   - 方案中规划的章节一旦撰写为 TXT 落地入库，必须**直接在方案中彻底删除该条目/单元**；
   - 同步更新方案中剩余待办章节的排期锚点与编号；
   - **严禁在方案文档中保留修改痕迹、版本迭代历史或更新日志**，完成的事情直接删干净，保持方案纯粹聚焦待办目标。

## 五、 写作禁忌与词汇使用准则（去机械感硬红线）

1. **严禁出现以下违禁词汇与表达**：
   - ❌ 严禁使用 **“一丝” / “一 丝”**。
   - ❌ 严禁使用 **“不易察觉” / “不易 察 觉”**。
   - ❌ 严禁使用 **“不容置疑” 等一切以“不容”开头的词汇**（如“不容置疑”、“不容抗拒”、“不容拒绝”等）。
   - ❌ 严禁使用 **“小猫”、“小兽”、“幼兽”等小动物类的比喻**（替换方案：直接填入“支配”、“掌控”、“狂热”等明确动词与形容词）。
   - ❌ **禁止描写成熟女性相关的描述**（例如“成熟女性的体热”、“成熟女性的体香”等；文中不存在此类成熟女性，即便你认为有，也绝对禁止出现此类描述）。
   - ❌ 严禁出现 **“他推了推并不存在的隐形眼镜”** 等荒诞突兀动作。
2. **句式与风格刚性约束**：
   - ❌ **不用“不是...是...”对比句式** —— 一律直接写肯定句，杜绝否定迂回。
   - ❌ **不用“不是”的句式** —— 叙事一律采用正面积极动作描写。
   - ❌ **不写“成本/效率/优化”等现代管理/工程用语**。
   - ❌ **不使用括号堆砌补充解释** —— 所有信息必须自然融入正文叙述。
   - ❌ **不写空泛金句结尾**（如“为……支撑”、“奠定……基础”等假深刻套话）。
3. **器官与生理词汇标准化使用指南**：
   NSFW 描写中如需涉及解剖与器官，直接使用以下标准词汇，杜绝模糊遮掩与现代生硬词：
   - **男性部位**：鸡巴、肉棒、屌、大屌、龟头
   - **女性部位**：奶子、乳头、阴唇、阴蒂、阴道、蜜穴、小穴、菊穴
