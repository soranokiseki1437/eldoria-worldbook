# 全库架构重构方案：从“终止条件”全面转向“标号情境慢推体系”（完善定稿）

> **状态**：第一步实施方案 · 最终定稿  
> **日期**：2026-09-19  
> **核心决策**：  
> 1. **原有情境内容零改动**：现有情境文本逐字100%保真，仅在每条行首添加规范数字标号（`- 1. `、`- 2. `...）；  
> 2. **条件3作为最后一条收束情境**：原终止条件3（纯物象收束文本）直接作为第 $N$ 条情境追加至末尾（经去重检查后），不改动前置情境文本；  
> 3. **新增 `总情境数` 字段**：章节TXT显式声明 `总情境数: {N}`，形成大纲与模型的强约束锚点；  
> 4. **彻底切除冗余字段**：全库彻底删除 `章节任务` 与 `章节终止条件`；  
> 5. **状态栏精准命名**：`<chapter_information>` 中使用 `大纲情境进度|第X条 / 共N条`；  
> 6. **完整保留两轮强制冷却机制**：当推进到第 $N$ 条（$X+1 = N$）时，必须依次经历“余韵互动”与“过渡互动”，严禁直接跳入下一章。

## 一、 核心痛点与本次重构的本质

长期以来，世界书体系中存在着三个互相冲突、互相重复的字段：
```text
【情境】        -> 3~8个时序事实（本该是叙事的真正节拍器）
【章节任务】    -> 1句话核心目标（与【核心】字段严重同质化）
【章节终止条件】-> 条件1(重复情境开头) + 条件2(粗暴串联整章出格与事后) + 条件3(环境物象收束)
```

### 痛点根源：
1. **条件2诱发AI跳剧情**：
   - 现行机制中，条件2往往一句话涵盖了“身体试探 ➔ 突破理智 ➔ 达到高潮 ➔ 离开现场 ➔ 回营坦白”。
   - 模型为了在状态栏标记条件2达成，在单次生成中把上述情境一口气全部写完，直接把原本细腻的情境条目当成流水账报销。
2. **重构后的解耦与纯粹**：
   - 砍掉任务与终止条件后，大纲只保留**纯粹带编号的情境链条（1..N）**；
   - 显式声明 `总情境数: N`；
   - 状态栏精准输出 `大纲情境进度|第X条 / 共N条`；
   - 模型注意力被强制锁定在当前这唯一的未完成条目上，从物理层面根除跳剧情。

## 三、 机制与指令文件联动重构方案

### 3.1 改造《游戏状态界面》（`docs/chapter/_游戏状态界面.TXT`）
`<chapter_information>` 精简重塑为：
```xml
<overall>
<chapter_information>
当前章节|第306章 矿道推车的盲区——避光石后的隔裤搓抚
下一章节|第307章
大纲情境进度|第2条 / 共5条
阶段|4：跨线
在场人物|哈根,Seraphina
</chapter_information>
<StatusBlock>
...
```
* **字段删除**：彻底移除 `章节任务` 和 `章节终止条件` 两行；
* **字段重构**：`章节进度` 重命名为 `大纲情境进度`，格式严格为 `第X条 / 共N条`；
  - $X$ 表示当前回复的正文刚刚展开完毕的情境条目编号；
  - $N$ 为大纲中显式标注的 `总情境数`。

### 3.2 改造《章节追踪指令》（`docs/chapter/_章节追踪指令.TXT`）
彻底移除关于“终止条件达成/更新”的逻辑，重写为**情境步进与强制冷却引擎**：

1. **大纲情境单步严格推进（Pacing Lock）**：
   - 每次接收到“继续”或推进指令时，AI必须比对上下文：上一回复已完成至第几条（记为 $X$）；
   - **本次回复强制且仅允许展开第 $X+1$ 条情境**；
   - **严禁跨步狂飙**：绝对禁止在单次回复中把第 $X+2$ 条及之后的剧情顺带写完！
2. **未尽防退场铁律（Anti-premature Closure）**：
   - 只要 $X+1 < N$（即尚未到达最后一条情境）：
     - 严格禁止让角色脱离当前场景、离开现场或转换场景；
     - 严格禁止提前触发事后宣泄完成或回营坦白；
     - 正文必须在第 $X+1$ 条情境的临界点、微动作或悬念处自然驻留，将接力棒交回给玩家。
3. **章节间强制冷却机制（完整保留并升级）**：
   - 当正文展开完毕第 $N$ 条情境（$X+1 = N$）时，**绝对禁止立即标记章节完成并跳到下一章**！
   - 必须严格执行**两轮强制冷却互动**：
     1. **第一轮·余韵互动**：事后沉默/肢体依偎/简单低语/环境音与微光描写，让事件充分沉淀。状态栏输出：`大纲情境进度|第N条 / 共N条（余韵沉淀）`；
     2. **第二轮·过渡互动**：时间自然流逝推进/整理衣物/离开场景/回归日常活动。状态栏输出：`大纲情境进度|第N条 / 共N条（过渡收束）`；
     3. **正式完成切换**：经历上述两轮冷却后，若玩家再次给出“继续”指令，才可在生成回复时将当前章节号+1，正式激活下一章节！

### 3.3 改造构建脚本（`scripts/build_eldoria.py`）
- 组装 `<章节剧情>` 时，移除 `[章节任务]:` 和 `[章节终止条件]:` 输出；
- 保留 `[总情境数]: N`；
- 保留 `[情境]:` 中的 `- 1. xxx` 标号格式，确保世界书 JSON 数据与文本规范完全对齐。

### 3.4 规则文档与历史方案清理
- **全面重构**：`docs/story/_TEMPLATE_RULES.md` 与 `docs/story/_TEMPLATE.TXT`；
- **直接删除**：`docs/story/_条件修复方案.md`（不再需要，彻底清理）；
- **同步更新**：`CLAUDE.md` 中的字段说明与验证规范。

## 四、 全库自动化迁移执行规划（安全第一）

全库 500+ TXT 文件将通过自动化脚本安全迁移：

1. **研发专用迁移脚本（`scripts/migrate_to_numbered_contexts.py`）**：
   - 解析 TXT；
   - 统计原情境数量，原情境文本**100%不做任何字词改动**，仅加上 `- 1. `、`- 2. `... 前缀；
   - 提取原 `章节终止条件:` 的第 `3.` 条文本：
     - 若原情境最后一条未包含该环境物象收束，则将其作为最后一条（第 $N$ 条）追加；
     - 计算总条数 $N$，写入 `总情境数: {N}` 字段；
   - 彻底删除 `章节任务:` 与 `章节终止条件:` 字段段落；
   - 保存回写。
2. **小步试跑与比对**：
   - 优先对 `4：跨线/306` 等 3 个样本章节进行试跑；
   - 审查 Git diff，确保原情境文字无一丝一毫改动、编号与总数完美对齐；
   - 用户验收后，再执行全库批量迁移。
3. **全库构建与一致性校验**：
   - 运行 `python scripts/rebuild_all.py`；
   - 运行校验工具确保无格式断裂。
