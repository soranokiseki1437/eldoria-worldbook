# 全库架构重构方案：从“终止条件”全面转向“标号情境慢推体系”

> **状态**：第一步实施方案 · 深度设计稿  
> **日期**：2026-09-19  
> **核心决策**：  
> 1. 条件3融入/对齐为最后一个情境条目（承载物象化收束，去重整合）；  
> 2. **彻底切除**全库 `章节终止条件` 与 `章节任务` 冗余字段；  
> 3. 章节TXT每条情境统一采用规范数字标号（`1.`、`2.`、`3.`...）；  
> 4. `<chapter_information>` 彻底删除终止条件与任务，章节进度重构为 `章节进度|第2条 / 共4条`；  
> 5. 同步重写《章节追踪指令》、《游戏状态界面》、《模板规则》，删除废弃的《条件修复方案》。

---

## 一、 为什么这次重构是“治本之策”？

长期以来，世界书体系中存在着三个互相冲突、互相重复的字段：
```text
【情境】        -> 3~8个时序事实（本该是叙事的真正节拍器）
【章节任务】    -> 1句话核心目标（与【核心】字段严重同质化）
【章节终止条件】-> 条件1(重复情境开头) + 条件2(粗暴串联整章出格与事后) + 条件3(环境物象收束)
```

### 痛点根源彻底暴露：
1. **诱发AI跳剧情的罪魁祸首就是“条件2”**：
   - 条件2为了在语法上闭合，往往把“发生触碰 ➔ 突破理智 ➔ 达到高潮 ➔ 事后掩饰 ➔ 回营坦白”一口气写在了一句话里。
   - AI为了让状态栏从 `进度1` 变成 `进度2/3`，在单次生成中必须把条件2的事全部做完，直接绑架了原本应该分步展开的情境条目。
2. **条件3与情境末尾割裂**：
   - 条件3本身是“摄影机撤出、纯物象收束（呼吸/环境音/光影）”，它天然就应当是叙事的**最后一个时空切片**。
   - 硬拆成独立字段，不仅导致AI在生成正文时无所适从，还极易与情境末尾发生重复或冲突。
3. **彻底切除后的质变**：
   - 砍掉任务与终止条件后，章节大纲只剩下纯粹的 **带有数字编号的情境链条（1..N）**。
   - 状态栏直接显示 `章节进度|第2条 / 共4条`，模型注意力与情境编号呈现 **1:1 绝对强绑定**。跳剧情的温床被从物理层面彻底连根拔起！

## 三、 机制文件联动改造方案

### 3.1 改造《游戏状态界面》（`docs/chapter/_游戏状态界面.TXT`）
彻底精简 `<chapter_information>`：
```xml
<overall>
<chapter_information>
当前章节|第306章 矿道推车的盲区——避光石后的隔裤搓抚
下一章节|第307章
章节进度|第2条 / 共5条
阶段|4：跨线
在场人物|哈根,Seraphina
</chapter_information>
<StatusBlock>
...
```
* **删减项**：`章节任务`、`章节终止条件` 彻底移除。
* **规则变更**：`章节进度` 格式严格为 `第X条 / 共N条`。
  - $X$ 表示当前回复中正文刚刚展开完毕的情境条目编号；
  - $N$ 为大纲中情境条目的总数。

### 3.2 改造《章节追踪指令》（`docs/chapter/_章节追踪指令.TXT`）
删除所有关于“终止条件1/2/3达成”和“条件冷却”的旧规则，重写推进引擎：
1. **情境单步严格推进（Pacing Lock）**：
   - AI在生成回复前，检查上文停留在情境第几条（假设为第 $X$ 条）；
   - **本次回复强制且仅允许展开第 $X+1$ 条情境**；
   - **严禁跨步**：绝对禁止在单次回复中把第 $X+2$ 条及之后的剧情一并写出！
2. **未尽防退场铁律（Anti-premature Closure）**：
   - 只要 $X+1 < N$（即大纲未到最后一条）：
     - 严格禁止让角色脱离当前场景、离开现场或转换场景；
     - 严格禁止提前触发事后坦白或宣泄完成；
     - 正文必须在第 $X+1$ 条情境的微动作或悬念处自然截断，等待玩家下一次输入。
3. **章节完成判定（Chapter Completion）**：
   - 仅当 $X+1 = N$（即最后一条情境展开完毕，环境物象淡出）时，才允许在下一次回复时将章节号+1，进入下一章。

### 3.3 改造构建脚本（`scripts/build_eldoria.py`）
- 组装 `<章节剧情>` 时，移除 `[章节任务]:` 和 `[章节终止条件]:` 输出；
- 保留 `[情境]:`（保留 `1.`、`2.`... 标号，方便模型读取对齐）；
- 移除对情境标号的误伤正则，确保编号完整注入世界书。

### 3.4 规则文档与历史方案清理
- **删除**：`docs/story/_条件修复方案.md`（彻底完成历史使命，直接移除）；
- **全面重构**：`docs/story/_TEMPLATE_RULES.md` 与 `docs/story/_TEMPLATE.TXT`，确立标号情境为唯一权威事实源；
- **同步更新**：`CLAUDE.md` 中的字段规格表。

## 四、 全库批量迁移与执行路线

全库500+章节如果手动修改工作量巨大，我们将采用**自动化专用迁移脚本 + 抽样复核**的方式进行：

1. **迁移脚本研发（`scripts/migrate_to_numbered_contexts.py`）**：
   - 遍历 `docs/story/` 下所有 `.TXT`；
   - 解析已有的 `情境:` 列表，自动为每一条加上 `1.`、`2.`、`3.`... 标号；
   - 读取原 `章节终止条件:` 的第 `3.` 条：
     - 比对是否与原情境末尾重复；
     - 若不重复且具备优质收束意象，将其作为最后一条 `N.` 情境条目追加；
   - 彻底删除 `章节任务:` 与 `章节终止条件:` 字段段落；
   - 保存写回。
2. **构建与验证联动**：
   - 运行构建脚本生成新的 JSON；
   - 运行验证脚本确保全库无一漏网。
